## IMPORTANT FINDINGS (2)

### I-1 — CI-job `gui-windows` упадёт на чистом checkout: `ocaml/dist-win/` нет в git

**File:** `.github/workflows/release.yml` (новый job, шаг «Build the OCaml decrypter»)
**Severity:** important — первый же пуш тега `v*` уронит релиз GUI-ассета.

`ocaml/dist-win/` игнорируется корневым `.gitignore` (`*.exe`, `*.dll`) и в git отсутствует (`git ls-files ocaml/dist-win` пуст). На раннере после checkout каталога нет, а `Copy-Item _build/default/bin/main.exe ../ocaml/dist-win/rpgm-decrypt.exe -Force` **не создаёт** недостающие каталоги → «Could not find a part of the path». Локально работает только потому, что каталог уже существует.

**Reproducer:** свежий clone → `pwsh: Copy-Item x ../ocaml/dist-win/rpgm-decrypt.exe -Force` → error.
**Fix:** перед копированием добавить
```pwsh
New-Item -ItemType Directory -Force ../ocaml/dist-win | Out-Null
```

### I-2 — в dist/zip подменяется zlib1.dll, парный сборке ядра

**File:** `gui/build_windows.ps1:128,133`; артефакты `gui/dist/zlib1.dll`, zip
**Severity:** important (низкий практический риск, но это не протестированная пара).

`Copy-Item $ZlibDll $dist` (строка 128) кладёт zlib из `ocaml/dist-win` (`1b998ab5…`, v1.3.2), но затем строка 133 заливает поверх весь flatten GTK-рантайма, среди DLL которого свой `zlib1.dll` (`11cd9117…`) — он и остаётся в dist и zip. ABI `zlib1.dll` стабилен, риск совместимости низкий, однако исполняемая пара exe+dll уже не та, с которой ядро собиралось/тестировалось.

**Fix:** переносить `Copy-Item $OcamlExe/$ZlibDll` **после** цикла копирования `$runtime` (или явно перезаписать zlib в конце).

## ADDENDUM 2 — Star Gate доведён до продакшена (2026-08-29, финал)

**OAuth:** зарегистрирован выделенный app «rpgm-decrypt GUI», client_id `Ov23liyHPi1XYLX3hrQB` вшит в `star_gate.rb` (секрет не нужен). Live-проверка device code — OK.

**Пойманные и исправленные баги на реальных запусках:**
1. **Краш по кнопке Sign-in** — `Thread#daemon=` не существует в Ruby (перенесено из Rust по памяти). Убрано; в Ruby воркеры и так умирают с главным потоком.
2. **TLS в packed exe: HTTP 0** — GTK-рантайм тащит свои `libcrypto-3-x64.dll`/`libssl-3-x64.dll`, которые затеняли ruby_builtin_dlls-версии (поиск DLL: app dir первым), а их скомпилированные пути к CA-сертификатам не существуют. Фикс: обе DLL исключены из staging; в бандл добавлен `cacert.pem`; `main.rb` ставит `SSL_CERT_FILE` до любого TLS. Ошибки сети теперь показывают реальную причину, а не «HTTP 0».
3. **Белый экран после Sign-in** — `GLib.markup_escape_text` не существует в ruby-gnome 4.x → `show_device` падал после `clear` и оставлял пустое окно. Заменено на локальный `xml_escape`; любое падение рендера теперь деградирует в экран ошибки с Retry, а не в белую пустоту.
4. **Главное окно не открывалось после Unlocked** (процесс умирал молча) — окно создавалось после `Gtk.main_quit`. Переделано на один `Gtk.main` для всего приложения: gate-окно при destroy внутри того же цикла передаёт эстафету `RpgmGui.new`. Покрыто автотестом `test_gate_transition.rb` (инжекция `:starred` без сети).
5. **Фриз окна при открытии браузера** — `system('cmd /c start …')` блокировал GTK main loop на время старта браузера. Заменено на `Process.spawn` + `detach` (и в `open_path` главного окна тоже).
